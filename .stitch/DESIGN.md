# Design System: ProtoAlign 原型对齐助手
**Project ID:** Pending Stitch connection

## 1. Visual Theme & Atmosphere
这是一个明亮、清晰、专业但不冷漠的桌面工作台。整体沿用用户认可稿的轻量 B 端产品气质：高信息密度由稳定栅格承载，留白用于分隔任务，不追求展示型大留白。左侧问题队列、中间问题上下文画布、右侧 Agent 检查器处于同一浅色视觉环境中，不强制使用三种背景；它们通过明确列宽、细分隔线、各自的 sticky 标题栏、内容容器和不同信息密度形成可感知的工作区。中间画布始终是视觉主舞台，左右两侧为支持决策的导航与检查器。

整体感觉应当 polished、trustworthy、approachable、structured。避免纯灰编辑器、粗野主义网格、深色工业控制台、蓝紫霓虹、玻璃拟态和平均分配的 Dashboard 卡片墙。视觉重点来自“问题、证据、原型位置和人的动作”之间的关系。

## 2. Color Palette & Roles
- **行动钴蓝（#2F5CF4）：** 品牌识别、主按钮、当前选中问题的描边或浅色高亮、主要链接与 Agent 关键提示。只在真正可操作或当前聚焦的位置使用。
- **通透纸白（#FFFFFF）：** 顶部导航、主要内容容器、原型画布和输入控件的基础表面。
- **轻雾背景（#F7F9FC）：** 应用底色与次级区域，用于形成轻微层次，而不是把三列切成三种强背景。
- **边界冷灰（#E5E9F2）：** 列分隔、标题栏下边界、卡片描边、证据容器和输入框边界。
- **主文字墨色（#202534）：** 页面标题、问题标题、判断和操作标签。
- **次级石板灰（#7D8597）：** 来源、时间、辅助说明、非当前状态。
- **阻塞珊瑚红（#FF4D4F）：** 阻塞问题编号、原型缺口标注和需要立即注意的风险；避免铺满大面积背景。
- **待确认琥珀橙（#F5A000）：** 待确认状态、澄清动作和资料未确定提示。
- **处理中清蓝（#3974E9）：** 正在处理的问题状态，与主行动色同色系但通过明度区分。
- **AI 推断柔紫（#7B61E8）：** 仅用于“AI 推断·待确认”来源标签，帮助用户区分它不是已确认事实。
- **已核验绿色（#22B573）：** 已检索、已检查、已核验和满足验证条件的结果。
- **风险提示浅橙底（#FFF7ED）与阻塞浅红底（#FFF3F2）：** 只用于小面积状态标签、警示条和证据重点，不充当整列背景。

颜色原则：品牌蓝负责行动与聚焦，红/橙/紫/绿负责语义跳色。问题列表中的跳色必须同时配合文字标签或图标，不依赖颜色单独传达状态。

## 3. Typography Rules
中文采用现代系统无衬线字体，正文优先清晰、紧凑和耐读；英文、版本号、日期与编号保持与中文一致的屏显气质。页面级标题使用中等偏粗字重，问题标题和关键判断使用半粗体，正文使用常规字重，来源与时间使用更轻的次级字色。禁止把等宽字体作为大面积正文，也不使用夸张营销型 display 字体。

字号层级保持克制：应用标题与页面标题约 18–22px，区块标题 14–16px，正文 13–15px，元信息 11–12px。行高强调扫描效率，长段解释保持 1.55 左右。问题编号、状态标签和按钮文字可适度加粗，形成清楚的任务层级。

## 4. Component Stylings
* **Buttons:** 主操作为钴蓝实心按钮，使用 gently rounded corners 与清楚的 hover/pressed 状态；次级操作为白底细描边；“接受风险”使用琥珀橙描边和浅橙 hover，不能与主操作争夺视觉中心。图标按钮保持紧凑并提供 tooltip。
* **Issue Rows:** 问题条目采用白色或极浅背景、细描边和 softly rounded corners。当前选中项使用品牌蓝描边与淡蓝聚焦表面。阻塞、待确认、处理中通过左侧状态点、编号底色和来源标签形成语义跳色，而不是整张卡大面积染色。
* **Cards/Containers:** 原型画布、证据摘要和 Agent 分析容器采用 softly rounded corners、1px 冷灰描边与 whisper-soft diffused shadow。卡片仅用于独立信息对象；页面分区主要依靠栅格和规则线。
* **Inputs/Forms:** 白色背景、清楚标签、冷灰描边、轻圆角；聚焦时出现钴蓝 focus ring。下拉选择器用于 V1–V4 版本切换。
* **Status Badges:** 紧凑标签，使用语义色的浅色底与深色文字；阻塞红、待确认橙、处理中蓝、AI 推断紫、已核验绿。标签文字必须明确，不使用只有颜色的小圆点替代全部语义。
* **Prototype Annotation:** 用珊瑚红虚线框、编号圆点和短标签定位问题；标注与右侧问题解释保持同一编号映射。
* **Agent Inspector:** 使用分段标题、规则线、勾选式验证条件、短段建议和固定底部操作区。聊天输入是辅助入口，不占据主要空间。

## 5. Layout Principles
桌面优先，目标画布约 1440×1024。顶部为紧凑全局导航，包含项目名、版本下拉、交付门槛、更新时间、检查设置和主操作。

主工作区采用三列 split view，但不要求三列使用不同底色：

- 左侧约 20–22%，负责问题分组、筛选与最近活动；内容可独立滚动。
- 中间约 52–56%，为最大工作区，展示版本工具栏、原型定位、关联证据和修改前后信息；内容层级最多。
- 右侧约 24–26%，为 Agent 检查器，展示问题解释、判断依据、验证条件、辅导提示与结构化动作。

三列通过连续的竖向分隔线、对齐一致但各自独立的标题栏、稳定内边距和内容密度差异形成区分。允许背景融合，但禁止标题、滚动区域和操作边界糊在一起。中间画布的容器宽度与留白应明显高于左右侧栏。

问题列表采用“阻塞问题 / 待确认 / 处理中”语义分组；中间原型标注与当前问题保持同编号；右侧操作区固定在可见范围。信息从左到右形成“选择问题 → 查看上下文 → 理解并决策”的阅读路径。
