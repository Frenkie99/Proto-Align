# ProtoAlign 面试演示与自助浏览脚本

推荐顺序：在线体验 → 约一分钟录屏 → GitHub。现场讲解约 5 分钟；面试官自行浏览时使用同一条路径。

## 1. 开场：先说产品对象（30 秒）

> ProtoAlign 不是给原型打分，而是围绕 Issue 管理资料证据、原型位置、人的决定和跨版本验证。Agent 负责查资料、检查 DOM 和提出草稿；产品经理确认事实、接受风险并决定是否关闭问题。

公开页面首次打开会显示“5 分钟看懂 ProtoAlign”。点击“开始浏览精选案例”，默认进入 Customer Service Agents 完整闭环。

## 2. Customer Service：看完整问题闭环（2 分钟）

1. 在左侧选择 Guardrails 问题。
2. 在中间查看 V1 原型位置和资料 / DOM 原文，强调 Issue 不是无依据建议。
3. 在右侧查看 Agent 的影响说明、判断依据、澄清问题和验收条件。
4. 点击左下角“活动追踪”，展示真实的 `search_sources`、`inspect_prototype`、`get_issue_context`、`compare_versions` 和 `save_verification` 事件。
5. 切换到 V2，查看“疑似已解决”的跨版本复检证据。
6. 强调 Agent 没有自动关闭问题：最终“已解决”来自产品经理填写依据后的人工操作。

## 3. OpenAgent：看输入变化带来的不同问题（45 秒）

1. 用左上角项目切换器打开 OpenAgent。
2. 浏览工具 / MCP 边界、知识库隔离、审计日志或 Loading 阻塞问题。
3. 说明同一个 Agent 面对另一类 AI 产品时，会根据实际资料和 DOM 改变检索词、检查位置和 Issue，而不是播放固定检查清单。

## 4. HuggingChat：看 Agent 的不确定性（60 秒）

1. 切换到 HuggingChat。
2. 打开“运行比较”。
3. 查看两次真实初评的共同主题、仅单次出现的问题、证据差异与严重程度变化。
4. 强调结果被明确标记为“有波动 · 待人工确认”，系统不会暗示模型输出具有不存在的确定性。

## 5. 真实试用：从空白项目开始（可选，60–90 秒）

1. 新建一个没有预置 Issue 的空白项目。
2. 导入至少一份文本资料或角色反馈。当前支持手工文本、TXT、Markdown 和 HTML 文本。
3. 导入一个公开 URL、单文件 HTML 或静态构建 ZIP；等待渲染后 DOM 采集。
4. 点击“启动评审”，等待 DeepSeek `deepseek-v4-pro` 真实调用工具。
5. 打开活动记录和生成的 Issue，确认它引用了本次输入的资料或 DOM。

公开试用有共享密码和每日 Agent 额度。请勿上传机密、客户或个人资料。额度、模型、文件解析或网页采集失败时会显示真实错误，不会回退到虚拟 Issue。

## 6. 结束语（20 秒）

> 普通大模型通常只针对一次输入给建议；ProtoAlign 保存资料、原型位置、问题状态、人的决定和版本历史。它的价值不是建议更多，而是让每个关键问题都有依据、有位置、有人确认，并能在新版本中复检。

## 当前真实边界

- 已实现：SQLite 项目存储、文本资料、公开 URL / HTML / 静态 ZIP、渲染后 DOM、真实 DeepSeek 工具调用、有证据 Issue、人工状态处理、版本复检、Run 比较和失败审计。
- 未实现：PDF / OCR、音频转写、Figma API、登录态、多页自动采集、截图视觉理解、正式多用户鉴权和长期云部署。
- 当前是预约式单机临时公网演示；电脑、应用进程和网络必须保持在线。
- 录屏对应真实 Customer Service V1→V2 项目，时长约 54 秒；它是备份和闭环概览，不替代网页中的可审计记录。
