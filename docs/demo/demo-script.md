# ProtoAlign 面试演示脚本

建议演示时长：5–7 分钟。

## 1. 先说明产品对象

打开工作台后先说：

> 这个产品不是给原型打分，而是围绕 Issue 管理客户反馈、研发约束、原型修改和跨版本验证。Agent 提取与比较，人确认事实并做最终取舍。

## 2. 展示项目上下文

1. 点击左上角项目名称。
2. 在“AI 客服回复助手”和空项目“合同审阅助手”之间切换。
3. 说明不同项目的资料、问题和记忆互相隔离；空项目必须先建立上下文。
4. 切回“AI 客服回复助手”。

## 3. 展示两级输入

1. 点击右上角“导入资料”。
2. 说明原型版本是被评审对象，客户 / 研发资料是评审依据。
3. 演示“录入角色反馈”：填写来源角色、标题、原文和原始位置。
4. 勾选“同时关联到当前选中的问题”并保存。
5. 回到画布，点击“关联证据”旁的“添加 / 关联”，展示问题只引用需要的项目资料。

## 4. 展示 Agent 不是一次性 Workflow

1. 点击“启动复检”。
2. 打开活动记录，说明只展示可核验的工具行动，不暴露隐藏思维链。
3. 新录入的角色反馈会先形成“待确认问题草稿”，不会自动成为正式需求。
4. 选择新问题，展示来源、待定位状态和需要产品经理确认的下一步。

## 5. 展示跨版本闭环

1. 再次打开“导入资料”，选择“导入原型版本”。
2. 指定 V3，并记录 Figma、网页或文件位置。
3. 启动复检后，版本切换到 V3，并显示 Agent 对历史验收条件的核验状态。
4. 强调三个通过项仍不代表自动关闭：最终验证与关闭权在产品经理手中。

## 6. 结束语

> 普通大模型只能针对一次输入给建议；这个 Agent 保留项目证据、问题状态、人的决定和版本历史。它的价值不是建议更多，而是减少问题遗漏、决策失联和“改了页面但没有解决问题”。

## 演示边界

- 文件解析、Figma API、音频转写和模型推理由真实 Agent 后端完成；当前高保真原型只演示对象关系与闭环。
- 页面会把新资料、证据关联、问题状态和生成的问题草稿保存到浏览器本地。
- 如果需要重新开始演示，可清除该页面的站点数据后刷新。
