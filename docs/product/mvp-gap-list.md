# ProtoAlign 剩余工作清单

## 当前已经证明的部分

高保真原型已经能够证明产品的主要对象关系和演示闭环：

- 用户在项目之间切换，不同项目拥有独立上下文；
- 原型版本与客户 / 研发等评审依据分开输入；
- 角色反馈先是待确认主张，不直接升级成正式需求；
- 资料可以在项目级管理，也可以在问题级关联；
- 原型已模拟“Agent 复检后生成待确认问题草稿”的交互，尚未发生真实模型推理与工具调用；
- 导入新版本后，历史问题进入人工验证而非自动关闭；
- 项目、输入、证据关系、问题状态和问题草稿保存在浏览器本地。

## 面试演示前仍需确认（P0）

1. **演示主线取舍**：正式演示只走一条“录入反馈 → 生成问题草稿”或“导入 V3 → 复检历史问题”的主线，另一条作为补充，避免信息过载。
2. **示例输入内容**：准备一条不会与现有四个问题重复的客户或研发反馈，并明确来源角色、时间和原文位置。
3. **Agent 可见边界**：活动记录继续只展示检索、解析、对照和结果，不展示隐藏思维链。
4. **页面肉眼验收**：在实际演示使用的浏览器尺寸下逐个点击项目切换、导入、关联、复检、基线确认和版本记录。
5. **重置演示状态**：正式演示前清除本地站点数据，确保新增问题和导入记录不会重复。

## 做成真实 Agent 必须补齐（核心能力为开发 P0）

1. **输入解析工具**：网页 DOM、PDF、图片 OCR、Figma 节点、文档与会议转写。
2. **结构化主张层**：把原文抽取为目标、事实、约束、建议、假设和待确认项，并保留引用位置。
3. **Agent Harness**：控制可用工具、运行步骤、重试、超时、人工审批和可观测日志。
4. **项目记忆**：分别保存原始证据、确认后的需求基线、问题状态、决策记录和版本差异。
5. **评审策略**：按需求一致性、流程完整性、异常场景、AI 风险和研发可交付性调用不同检查器。
6. **版本比较与验证器**：比较新旧原型变化，并按每个 Issue 的验收条件生成“通过 / 未通过 / 无法判断”。
7. **人工确认机制**：需求基线、冲突取舍、角色结论和最终关闭必须是显式批准动作。
8. **模型评测**：建立固定样例，检查证据引用正确率、问题有效性、遗漏、错误关闭和幻觉。

## 企业内部使用后再考虑（P2）

- 组织权限、项目成员与客户资料隔离；
- 飞书 / Figma / Axure / Jira 等第三方集成；
- 多人评论、通知和责任人协作；
- 研发交付包与客户确认包导出；
- 组织级评审规则和历史项目知识复用。

## 当前最危险的产品错误

- 把客户或售前反馈直接当正式需求；
- 把 AI 推断包装成事实；
- 只看新版本“有变化”就自动关闭问题；
- 原型版本和评审证据混在同一个上传列表中；
- 为了展示 Agent 而显示伪造的思维链或后台自主运行；
- 让大量低价值问题淹没真正阻塞交付的三到五个问题。
