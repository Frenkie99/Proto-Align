# ProtoAlign 产品使用逻辑

## 1. 核心对象层级

```text
项目 Project
├── 被评审对象：原型版本 Prototype Version
├── 项目资料：Source
│   ├── 需求与业务文档
│   ├── 客户 / 售前 / 研发反馈
│   ├── 会议纪要、录音与转写稿
│   └── 决策记录与历史材料
└── 问题 Issue
    ├── 关联证据 Evidence Link
    ├── 原型位置 Prototype Location
    ├── 人的决定 Decision
    └── 跨版本验证 Verification
```

原型与资料不能混成同一种上传物：原型是被检查、比较和验证的对象；客户、研发及业务资料是形成评审判断的依据。Issue 不复制整份资料，而是保存对具体来源位置的关联。

## 2. 项目入口

页头项目名称是单选项目切换器，不是复选框。一次工作只进入一个项目上下文：

- 点击当前项目名称，切换已有项目；
- “查看全部项目”进入项目列表；
- “新建项目”从导入首批资料或原型开始；
- 没有资料的新项目显示空状态，不能复用另一个项目的问题与证据。

## 3. 输入入口

### 项目级「资料与输入」

负责建立 Agent 可持续使用的项目上下文：

- 导入原型版本：Figma 链接、可运行网页、HTML、PDF、截图；
- 上传项目资料：需求文档、PRD、合同、流程图、研发记录；
- 导入会议材料：音频、转写稿或会议纪要；
- 手动录入角色反馈：保留客户、研发、售前等来源角色及原文。

所有输入先进入“待解析 / 待确认 / 待复检”状态。Agent 的抽取不能自动成为事实或正式需求。

### 问题级「添加 / 关联证据」

负责给当前 Issue 补充依据：

- 从项目资料中关联已有证据；
- 直接新增一条客户或研发反馈；
- 保留证据来源，允许之后解除或更换关联；
- 新增反馈仍是待验证主张，需要复检后才能形成问题草稿。

## 4. MVP 演示闭环

```text
选择项目
→ 导入原型版本与评审资料
→ Agent 解析资料并生成待确认主张
→ 产品经理确认 / 修正
→ Agent 复检并生成问题草稿
→ 问题关联证据与原型位置
→ 产品经理选择处理方式
→ 导入新版本
→ Agent 对照验收条件
→ 产品经理最终关闭、延后或接受风险
```

其中，需求基线确认、冲突取舍、来源角色确认和最终问题关闭必须由人完成。

## 5. 当前高保真原型已经覆盖

- 项目下拉切换与空项目状态；
- 独立的项目级资料输入中心；
- 原型版本、角色反馈、项目文件和会议材料入口；
- 可人工确认的需求 / 约束基线与真实版本记录；
- 问题级新增 / 关联证据；
- 新增反馈经复检形成待确认问题草稿；
- 新版本导入后进入历史问题复检；
- 本地保存项目、资料、证据关系和生成的问题草稿；
- 窄屏侧栏降级和核心按钮反馈。

## 6. 原型没有伪装完成的部分

- 文件正文解析、音频转写和 Figma API 读取；
- 真实模型推理、工具调用与 Agent 运行时；
- 服务端数据库、权限、多人协作和审计日志；
- 全部项目列表、新建项目向导和项目删除；
- 自动定位任意 Figma 节点或复杂动态交互；
- 真实导出研发交付包。

这些属于开发层，不应通过静态交互假装已经实现。
